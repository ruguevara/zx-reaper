# 5f. Sound

All sound is made with the beeper: bit 4 of port $FE toggled in busy-wait
loops. Five effects are generated by the game's own loops and one, the bell
chime, by the ROM's BEEPER routine. The game stops while a sound plays. The T
key mutes everything by masking the speaker bit out of every write.

## The sound mask

Every routine that writes port $FE for sound does it like this
([PlayRisingTone](../src/guards.asm#L94)):

```asm
  LD HL,SoundMask
  ...
  LD A,ULA_OUT_MASK       ; $1F: border white, speaker bit 4 set
  AND (HL)                ; $1F = sound on, $07 = sound off
  OUT (ULA_PORT),A
  ...                     ; DJNZ loop: half a period
  LD A,WHITE              ; $07: speaker off, border white
  OUT (ULA_PORT),A
```

[SoundMask](../src/variables.asm#L89) is $1F (on) or $07 (off). With $07 the first `OUT` writes 7,
the same as the second: the border stays white and the speaker never moves.
The timing loops still run, so a muted game runs at the same speed, except for
the bell chime, which is skipped entirely when muted (its delay is used
instead).

[CheckSoundKey](../src/events.asm#L658) reads half-row $FB (Q-T) on every pass and acts on the
key-down edge of T (bit 4): the previous state is kept in [SoundKeyState](../src/variables.asm#L97),
so holding T toggles only once. Each press XORs the mask with $18. [Start](../src/main.asm#L52)
sets the mask to $1F and the key state to "up" ($10) once at load time; the
setting survives games.

## The effects

| Sound | Routine | Construction | Length (from the routine headers) |
| --- | --- | --- | --- |
| rising sweep (title, game over) | [PlayRisingTone](../src/guards.asm#L94) | 16 steps, half period 8·C loop passes for C = 16 ... 1, 10 cycles per step | about 0.08 s |
| wrap tone | [PlanMoves](../src/movement.asm#L237) | the same sweep with 8 cycles per step | about 0.07 s |
| score chirp | [ShowScore](../src/sprites.asm#L169) | 16 steps of one cycle, half period 128 ... 8 | about 8 ms |
| guard eaten | [CheckGuardContact](../src/events.asm#L27) | 15 steps of 8 cycles, half period 8·(15 - C), so it falls; each delay pass reads and writes (IX+0), 51 T-states | about 0.25 s |
| death noise | [HoraceDies](../src/events.asm#L175) | 45 × 20 cycles, each half a random 64-255 loop passes | about 1 s with the colour animation |
| bell chime | [PaceAndChime](../src/events.asm#L693) | ROM BEEPER: DE = $16, HL = $0193 (about 1010 Hz) and DE = $1A, HL = $0168 (about 1120 Hz), in either order | about 22 ms per tone |

In the guard-eaten buzz the first step has C = 15, so the half period is
8 · 0 = 0, which `DJNZ` treats as 256: the first note is long and low
instead of short and high (the source calls it an accident).

The game-over sequence is 20 calls of [PlayRisingTone](../src/guards.asm#L94) with a colour flood
between them, the title loop one call per pass.

## The chime and interrupts

The game runs with interrupts disabled. The ROM BEEPER routine at $03B5
runs with interrupts disabled and enables them on return (standard ROM
behaviour), so [PaceAndChime](../src/events.asm#L693)
follows each `CALL ROM_BEEPER` with `DI`. The chime plays when the bell's
animation counter [BellTick](../src/variables.asm#L292) has its low six bits at 0 (low tone, then
high) or $20 (high, then low): twice per 64 passes while the bell is in the
maze, never after it has been taken.
